# คุยวง by FIBO99

ห้องสนทนาสดของ FIBO99 สำหรับวงเล็ก ๆ คุยด้วยข้อความ เสียง กล้อง และแชร์หน้าจอในห้องเดียวกัน สร้างห้องแล้วส่งลิงก์หรือรหัสให้กันได้เลย ไม่ต้องสมัครสมาชิก

แบรนด์ที่แสดงบนหน้าเว็บคือ **คุยวง by FIBO99** และ **เจ้าของ: FIBO99**

รองรับประมาณ 2–6 คนต่อการสนทนา ใช้ WebRTC แบบเมช (แต่ละเครื่องเชื่อมถึงกันตรง ๆ) และใช้ Socket.IO เป็นช่องสัญญาณกับแชต

## สิ่งที่ต้องมี

- Node.js 22 ขึ้นไป (ใช้ SQLite ในตัวของ Node)
- เบราว์เซอร์ที่รองรับ WebRTC (Chrome, Edge, Firefox, Safari)

ไมโครโฟนและกล้องใช้ได้บน `localhost` หรือเว็บที่เป็น HTTPS เท่านั้น ถ้าผู้ใช้ไม่ให้สิทธิ์ แชตข้อความยังใช้ได้

## รันบนเครื่องตัวเอง

```bash
npm install
npm run dev
```

เปิด http://127.0.0.1:4721

1. สมัครชื่อบัญชีกับรหัสผ่าน แล้วกด **สร้างห้องใหม่** คนที่สร้างห้องขณะล็อกอินจะเป็นเจ้าของห้อง
2. กดไอคอนคัดลอกข้างรหัสห้อง แล้วเปิดลิงก์นั้นในอีกแท็บหรือส่งให้เพื่อน
3. เพื่อนสมัครหรือเข้าสู่ระบบด้วยชื่อเดิมเพื่อให้ยศติดตัว หรือเข้าแบบผู้มาเยือนโดยไม่สมัคร
4. พูด เปิดกล้อง แชร์หน้าจอ หรือพิมพ์ข้อความได้เลย ปุ่มไมค์ กล้อง และแชร์จออยู่ข้างกัน

เข้าสู่ระบบด้วยชื่อบัญชีและรหัสผ่านเดิมอีกครั้ง ยศ สีชื่อ และการถูกปิดแชต ไมค์ หรือแชร์จอจะกลับมาเหมือนเดิม เพราะเก็บบนเซิร์ฟเวอร์ ไม่ได้อยู่แค่ในเบราว์เซอร์

เปลี่ยนพอร์ตได้ด้วยตัวแปร `PORT`

```bash
PORT=5000 npm run dev
```

## รันแบบโปรดักชัน

```bash
npm install
npm run build
npm start
```

`npm run build` สร้างหน้าเว็บไว้ที่ `dist/client` และเซิร์ฟเวอร์ไว้ที่ `dist/server.js` คำสั่ง `npm start` เสิร์ฟทั้งหน้าเว็บและ WebSocket จากโปรเซสเดียว

## ให้คนอื่นเปิดจากอินเทอร์เน็ต

กล้องและไมค์จะทำงานก็ต่อเมื่อเว็บอยู่บน HTTPS (ยกเว้น localhost) โฮสต์ต้องเป็นโปรเซสที่รันค้างไว้ได้ และต้องรับ WebSocket ได้ โฮสต์แบบ serverless ที่ไม่มีกระบวนการค้าง (เช่น ฟังก์ชันสั้น ๆ) ใช้กับแอปนี้ไม่ได้

### Docker

```bash
docker build -t khuiwong .
docker run --rm -p 4721:4721 -v khuiwong-data:/app/data khuiwong
```

ใส่ TURN ตอนรันได้ เช่น

```bash
docker run --rm -p 4721:4721 \
  -e TURN_URLS=turn:turn.example.com:3478 \
  -e TURN_USERNAME=user \
  -e TURN_CREDENTIAL=pass \
  khuiwong
```

### VPS

บนเซิร์ฟเวอร์ที่มี Node 22:

```bash
git clone <ที่อยู่รีโปนี้>
cd <โฟลเดอร์โปรเจกต์>
npm install
npm run build
PORT=4721 npm start
```

ใช้ reverse proxy (Caddy, nginx, Traefik) รับ HTTPS แล้วส่งต่อไปที่พอร์ตของแอป ทั้ง HTTP ปกติและ WebSocket (`Upgrade`) ต้องถูกส่งต่อ ตัวอย่าง Caddy:

```
talk.example.com {
  reverse_proxy 127.0.0.1:4721
}
```

### Render

ในรีโปมี `render.yaml` สำหรับเว็บเซอร์วิสเดียว แพลนฟรี ภูมิภาคสิงคโปร์ ถ้าต่อ GitHub แล้วสร้าง Blueprint จากไฟล์นี้ Render จะใช้คำสั่งดังนี้

- Build: `npm ci --include=dev && npm run build`
- Start: `npm start`
- Health check: `GET /api/health` (มี `GET /health` ด้วย)

`npm start` รัน `node dist/server.js` ด้วย `NODE_ENV=production` โปรเซสฟัง `process.env.PORT` ที่ Render ส่งมา และผูกที่ `0.0.0.0` หน้าเว็บที่บิลด์แล้วถูกเสิร์ฟจากโปรเซสเดียวกัน พร้อม WebSocket ของ Socket.IO ต้องใช้ Node 22 ขึ้นไป (ดู `engines` ใน `package.json` และไฟล์ `.node-version`)

`--include=dev` จำเป็นเพราะตัวแปร `NODE_ENV=production` ทำให้ `npm install` ข้ามเครื่องมือบิลด์ (TypeScript, Vite, esbuild) ถ้าไม่ใส่แฟล็กนี้ บิลด์จะไม่ผ่าน

โฟลเดอร์ข้อมูลตั้งด้วย `DATA_DIR` (ค่าใน Blueprint คือ `/opt/render/project/src/data`) แอปสร้างโฟลเดอร์นี้เองถ้ายังไม่มี ข้างในมี `khuiwong.sqlite` และ `uploads/`

แพลนฟรีไม่มีดิสก์ถาวร ทุกครั้งที่บริการรีสตาร์ทหรือเครื่องหลับแล้วถูกปลุก บัญชี ยศ แบน และไฟล์เพลงจะหาย เครื่องฟรียังหลับหลังไม่มีคนใช้ประมาณ 15 นาที สายที่กำลังคุยจะหลุด แล้วเปิดใหม่ได้แต่ห้องในหน่วยความจำไม่เหลือ

เมื่ออยากเก็บข้อมูลข้ามการรีสตาร์ท ให้เปลี่ยนแพลนเป็น Starter (หรือสูงกว่า) แล้วเพิ่มดิสก์ใน `render.yaml`

```yaml
disk:
  name: khuiwong-data
  mountPath: /var/data
  sizeGB: 1
```

แล้วตั้ง `DATA_DIR=/var/data` แพลนฟรีติดดิสก์ไม่ได้

ให้บริการพวกนี้รัน `npm run build` แล้ว `npm start` และเปิดพอร์ตจากตัวแปร `PORT` ที่แพลตฟอร์มกำหนด ตรวจว่าแพลตฟอร์มไม่ได้ปิด WebSocket

## บัญชี ยศ และการดูแลห้อง

สมัครชื่อแล้วรหัสผ่านถูกแฮชด้วย scrypt เซสชันเป็นโทเคนสุ่มที่แฮชไว้ใน SQLite (`$DATA_DIR/khuiwong.sqlite` ค่าเริ่มต้นคือ `data/khuiwong.sqlite`) อายุ 30 วัน เบราว์เซอร์เก็บเฉพาะโทเคน

คนที่กดสร้างห้องขณะล็อกอินคือเจ้าของห้องคนนั้นถาวร ยศมีหกระดับ เรียงจากสูงไปต่ำ: เจ้าของ, ผู้ดูแล, ผู้ช่วย, วีไอพี, สมาชิก, ผู้มาเยือน คนที่มีบัญชีแต่ยังไม่ถูกตั้งยศจะเป็นสมาชิก คนที่ไม่ได้ล็อกอินเป็นผู้มาเยือน

เจ้าของและผู้ดูแลตั้งยศได้ไม่เกินยศตัวเอง เปลี่ยนสีชื่อรายคน และสีเริ่มต้นของแต่ละยศ ผู้ช่วยเตะ ปิดแชต ปิดไมค์ และห้ามเปิดกล้อง ไมค์ หรือแชร์หน้าจอได้กับคนที่ยศต่ำกว่า เจ้าของกับผู้ดูแลแบนได้ด้วย การแบนบัญชีจำข้ามการเข้าใหม่ ผู้มาเยือนไม่มีบัญชี จึงแบนได้เฉพาะชื่อคู่กับแฮชของไอพี

ตั้งยศต่ำสุดที่เปิดไมค์ กล้อง หรือแชร์หน้าจอได้จากแผงจัดการ ค่าเริ่มต้นของแชร์หน้าจอคือสมาชิกขึ้นไป ผู้มาเยือนจึงแชร์ไม่ได้จนกว่าผู้ดูแลจะลดยศขั้นต่ำ ถ้าใครถูกจำกัด แชตข้อความยังใช้ได้ยกเว้นถูกปิดแชต

ถ้าตั้ง `OWNER_SECRET` ใน environment คนที่ล็อกอินและรู้รหัสนี้กดยืนยันในแผงจัดการเพื่อรับยศเจ้าของห้องได้ รหัสนี้ไม่ถูกเขียนลงฐานข้อมูล ใช้ตอนกู้ห้องที่ไม่มีเจ้าของ หรือย้ายสิทธิ์เจ้าของ

### เจ้าของเว็บ FIBO99

บัญชี `fibo99` เป็นเจ้าของเว็บทั้งระบบ ตั้งด้วยตัวแปรสภาพแวดล้อม (ดู `.env.example`)

- `SITE_OWNER_USERNAME` ค่าเริ่มต้นคือ `fibo99`
- `SITE_OWNER_PASSWORD` รหัสผ่านของบัญชีนั้น ความยาว 8–72 ตัว

ตอนเซิร์ฟเวอร์สตาร์ท ถ้าตั้งรหัสไว้ ระบบจะสร้างบัญชีนี้ถ้ายังไม่มี หรืออัปเดตรหัสถ้ามีอยู่แล้ว แล้วยกยศเจ้าของให้ในทุกห้องที่มีอยู่ในฐานข้อมูล ห้องที่ถูกสร้างหลังจากนั้นก็ได้ยศเจ้าของเช่นกัน บัญชีนี้ดูแลคนในห้องได้เหนือกว่ายศเจ้าของห้องคนอื่น และไม่มีใครลดยศหรือเตะบัญชีนี้ได้

ถ้าไม่ตั้ง `SITE_OWNER_PASSWORD` ชื่อนี้ถูกสงวนไว้ ไม่มีใครสมัครชื่อนี้ได้ และยังไม่มีบัญชีให้เข้าสู่ระบบ จนกว่าจะตั้งรหัสแล้วรีสตาร์ท

อย่าเขียนรหัสลงใน git บน Render ใส่ค่าในแดชบอร์ด `SITE_OWNER_PASSWORD` ใน `render.yaml` ถูกตั้งเป็น `sync: false` เพื่อให้กรอกในแดชบอร์ด

หน้าล็อบบี้และในห้องมีลิงก์ให้กดติดตาม FIBO99 ที่ Facebook, X (`@Coach_Signal`) และ YouTube ลิงก์เปิดแท็บใหม่

## ดีเจ

ยศวีไอพีขึ้นไปอัปโหลดไฟล์เสียง (mp3, wav, ogg, m4a, webm ไม่เกิน 12 MB สูงสุด 20 เพลงต่อห้อง) แล้วกดเล่น หยุด ข้าม หรือลบได้ ไฟล์อยู่ที่ `$DATA_DIR/uploads` (ค่าเริ่มต้น `data/uploads`) จังหวะเล่นซิงก์จากนาฬิกาของเซิร์ฟเวอร์ ทุกคนได้ยินเพลงเดียวกัน คนฟังปรับความดังของตัวเองได้ เพลงไม่ได้ผสมเข้าไมโครโฟน จึงไม่หลุดซิงก์ตามเน็ตของดีเจ

## แชร์หน้าจอ

ปุ่ม **แชร์หน้าจอ** อยู่ข้างปุ่มไมค์และกล้อง กดแล้วเลือกทั้งจอ หน้าต่าง หรือแท็บ ถ้าเบราว์เซอร์มีช่องให้เปิดเสียงของแท็บหรือเสียงระบบ เสียงนั้นจะถูกส่งไปด้วย

คนในห้องเห็นจอแชร์แบบไลฟ์สตรีม จอกินพื้นที่ส่วนใหญ่ของห้อง มีป้าย **LIVE / กำลังแชร์จอ** และชื่อคนแชร์ ภาพจากกล้องของทุกคนรวมถึงคนที่กำลังแชร์ย่อลงเป็นแถบเล็กด้านล่าง กด **เต็มจอ** หรือคลิกที่จอเพื่อขยาย กดอีกครั้งเพื่อออก

ภาพแชร์ขอความละเอียดสูงสุดประมาณ 1080p ที่ 30 เฟรมต่อวินาที และส่งเป็นแทร็กเพิ่มบนการเชื่อมต่อ WebRTC เดิม เมื่อมีคนเข้ามาใหม่หรือกดเริ่มแชร์ ระบบต่อรองการเชื่อมต่อใหม่ให้เอง หยุดได้จากปุ่ม **หยุดแชร์หน้าจอ** หรือจากปุ่มหยุดของเบราว์เซอร์ แถบจอจะหายไปทันที

มือถือส่วนใหญ่ยังเรียกแชร์หน้าจอไม่ได้ ปุ่มจะถูกปิดพร้อมคำอธิบายภาษาไทยให้ใช้คอมพิวเตอร์ ใช้ได้บน Chrome, Edge, Firefox และ Safari รุ่นเดสก์ท็อป ที่เปิดผ่าน localhost หรือ HTTPS

## STUN และ TURN

แอปใส่เซิร์ฟเวอร์ STUN สาธารณะของ Google ไว้แล้ว:

- `stun:stun.l.google.com:19302`
- `stun:stun1.l.google.com:19302`

STUN พอสำหรับการคุยในวงแลนเดียวกัน และเครือข่ายบ้านจำนวนมาก ถ้าผู้ใช้อยู่หลังเน็ตเวิร์กที่เข้ม (เช่น เน็ตองค์กรหรือ NAT แบบสมมาตร) ต้องมี TURN ถึงจะส่งภาพและเสียงถึงกัน ตั้งค่าผ่าน environment หรือไฟล์ `.env` (ดูตัวอย่างใน `.env.example`)

```bash
TURN_URLS=turn:turn.example.com:3478,turns:turn.example.com:5349
TURN_USERNAME=your-user
TURN_CREDENTIAL=your-password
```

`TURN_URL` ใช้แทน `TURN_URLS` ได้ถ้ามีที่อยู่เดียว เบราว์เซอร์ขอค่าเหล่านี้จาก `GET /api/config` ตอนเข้าห้อง รหัส TURN จึงต้องเป็นรหัสที่แจกให้ไคลเอนต์ใช้ได้ (แบบที่ใช้กับ coturn) ไม่ใช่รหัสลับของเซิร์ฟเวอร์อย่างอื่น

ตรวจว่าเซิร์ฟเวอร์ยังทำงานได้ที่ `GET /api/health`

## ข้อจำกัด

- ข้อความแชตอยู่ในหน่วยความจำ เมื่อทุกคนออกจากห้องหรือรีสตาร์ทเซิร์ฟเวอร์ ข้อความหาย บัญชี ยศ สีชื่อ การแบน และเพลย์ลิสต์อยู่ใน SQLite
- ไม่มีการล็อกอิน ไม่มีประวัติย้อนหลัง และไม่มีบันทึกไฟล์เสียงหรือวิดีโอ
- การโทรเป็นเมช แต่ละคนส่งสตรีมถึงทุกคนในห้อง เหมาะกับไม่เกิน 6 คน แชร์หน้าจอเพิ่มแทร็กภาพอีกเส้น จึงกินแบนด์วิดท์มากขึ้น มากกว่า 6 คนจะกินแบนด์วิดท์และซีพียูเร็ว
- ไม่มีข้อความส่วนตัว และไม่มีตัวยกมือ
- แชร์หน้าจอบนมือถือส่วนใหญ่ยังใช้ไม่ได้
- ถ้าไม่ได้ตั้ง TURN ผู้ใช้บางเครือข่ายจะเห็นกันและได้ยินกันไม่สำเร็จ แต่แชตข้อความยังใช้ได้
- เบราว์เซอร์อาจบล็อกเสียงอัตโนมัติ ถ้าเกิดขึ้นจะมีปุ่ม **แตะเพื่อเปิดเสียง** บนภาพของอีกฝ่าย
